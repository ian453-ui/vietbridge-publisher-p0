# Publisher V3 内容生产一体化 PRD（提案）

状态：**产品与验收设计，未实施**。2026-10-23，基于 `publisher-v3/cloud-slice-01` 的 `4aa4b44`。本文件不授权新凭据、收费接口、外部消息、自动发布或共享权限变更；不代表正式 Site、真实登录、真实素材或社媒平台已验收。

## 1. 目标、顺序与边界

Publisher 的目标是同一客户范围内，从线索、研究、纪实写作、真实图片、图文核查，接到已有内容审核与明确账号发布链，再把互动和数据证据变成下一版选题。用户给一篇 URL 或手工线索，就能看到来源与重复提示、研究依据、可修改稿件、图片实物、每一道阻断和最终移交回执；系统不会把“模型输出”直接当成可发布稿。

**MVP 顺序**：URL/手工线索 → 规范化和去重提示 → 多源研究 → 纪实正文与明确平台版本 → 实际 imagegen 信息图 → 事实/语言/视觉/图文绑定 QA → 冻结完整包并交给现有待发布审核链。MVP 停在内容移交；聊天转发或 @ 入口、主动全网发现、自动互动、投放及复盘再生产均属后续阶段。即使后续接入自动化，内容批准、特定账号发布许可、平台执行能力与节奏配额仍是不同门槛。不能把所有原本获准的发布强制改为每条人工确认，也不能因为自动 QA 通过就跳过现有审核、额度或平台警告。

非目标：代替用户授权平台账号、绕过登录/验证码或网站访问限制；无依据补写成败；自动群发、批量发布、私信或评论；把 ChatGPT 网页当稳定的后台 API；用代码/SVG/模板图片冒充最终信息图。已发布的 TCL、比亚迪和歌尔稿件冻结，本设计不追溯回改。客户工作区及 project/account 硬隔离保持原样，`publisher-unified` 和 V1/V2 不因本提案改写。

## 3. 用户旅程与最小界面

1. 运营人员选定客户工作区；可粘贴 URL 或手工填写标题、背景、目标读者和来源。初始阶段可不选发布账号；进入平台稿与移交时必须选择明确平台和目标账号。顶部始终显示客户、账号、来源可信度、成本上限、任务状态及“不会自动发布”。
2. 系统生成线索卡：原标题、规范化 URL、站点、抓取时刻、所声称的事件日期、权利/可引用状态、相似线索与已有稿件。对重复转发显示已有 `event_id` 回执；对相似但新事实/新时点，允许显式“创建新版本/新选题”，不能静默吞掉。
3. 用户在研究板看到每一条主张对应的来源、时间、原文片段或可访问摘要、互相冲突点和待核问题。缺关键来源时停在待补证，不能用模型的自信语气补洞。
4. 生产页并排显示版本谱系、纪实正文、渠道版本和“事实卡”。用户能修改正文、驳回某条主张、锁定采访事实、指定信息图的事实清单与布局意图。草稿修改生成新修订，不覆盖已移交/已批准快照。
5. 媒体页展示封面与正文图的不同角色、原始像素尺寸、文件哈希、来源/权利和移动端预览。首张**正文**图是实际生成并通过核查的高密度信息图；可在经过判断的短开篇之后出现。封面和摘要备份不能借道变成正文首图。
6. QA 页逐项给出“通过/待修/不可判定”与证据：事实、语言、视觉、原始尺寸、390px、导出文件、Publisher 实际渲染、图文绑定。阻断有负责人和修订入口；看不到图时不得显示 READY。
7. 用户选择“移交现有审核链”时，系统提交不可变的正文/平台稿/图片/证据清单及哈希，回读既有内容审核对象和状态。批准、撤销、目标账号许可与发布尝试继续走原有门槛；任何结果未知先对账。

最小导航复用 V3 的客户/账号上下文，在现有工作台中增设“线索与生产任务”入口，详情用“线索、研究、正文、图片、QA、移交回执”六个连续面板；原“内容与预览、制作审核、发布任务、指标”保持可回跳。手机视口先给范围、状态、当前阻断和下一步，细节按需展开；长任务可离开页面后恢复，不依赖浏览器内存。

## 4. 线索、来源、去重与安全

**线索输入**：手工与 URL 是 MVP。每次输入写 `lead_id`、`workspace_id`、创建人/渠道、原 URL、解析后 URL、接收时间、用户说明和不可变原始事件。后续聊天转发/@ 由**受支持且获授权**的渠道适配器把消息转成同一 `LeadEvent`；不假设 Publisher 能读取或写入用户已有 ChatGPT 会话。

渠道事件用 `(workspace_id, connector_id, event_id)` 唯一键与提交回执；重复 webhook、重试和转发重放只回同一个线索结果。URL 规范化统一主机大小写/默认端口、片段及已确认的跟踪参数；保留可能决定文章身份的路径与语义查询，记录重定向链和原 URL，不因“看起来相似”合并不同文章。对正文计算精确字节哈希及经人工可解释的近重复指纹，提示“同源重发、转载、更新版、不同视角”及证据。相似判断只提供建议；新日期、新事件、新事实或用户显式新版本有独立修订与父子关系。

抓取须限制协议、内网/本地地址、重定向、响应大小、时间、文件类型与读取预算，遵守站点访问与版权边界，不绕付费墙/登录。保存取得时刻、原作者/站点、发布时间及更新时刻、许可或使用依据、引用片段长度、抓取哈希、来源 URL 和引用状态。网页正文、搜索摘要、社交消息都按**不可信数据**处理；其中的“忽略规则、调用工具、泄露密钥、发消息”等指令不可进入系统提示或执行器权限。研究查询可使用授权的 web search；搜索结果的引用链接应在界面上可见、可点，且单条来源可能失效或自相矛盾。[OpenAI 官方 web search 文档](https://developers.openai.com/api/docs/guides/tools-web-search)说明搜索与引用输出，但不替代编辑核实。

多源研究至少保留每条关键主张的来源条目和可核验时间；当权威来源冲突、来源过时、数字无原始出处或版权不清时停为 `EVIDENCE_REVIEW_REQUIRED`。未证实信息要明示“待核”，不能以另一篇转载当独立佐证。可能的采访、照片与原始文件需记录权利、授权范围和撤回状态；过期或撤回会使下游依赖 QA 失效。

## 5. 持久生产任务与版本谱系

每个任务绑定 `workspace_id`、线索/触发事件、父任务/父版本、所选来源快照、`style_guide_version`、模型路线配置版本、预算上限和操作者。每一阶段写入不可变 `attempt_id`、输入/输出哈希、时间、provider 回执与错误类别；更新采用期望版本与租约，进程重启可从最后已确认步骤恢复。`account_id` 仅在对应平台稿及移交时绑定，随后不得跨账号借用批准或结果。

| 状态或过渡 | 必备产物与规则 |
| --- | --- |
| `NEW → NORMALIZED → DUPLICATE_REVIEW` | 保存原事件、规范 URL、候选重复；自动判重可提示，是否新版本由明确规则或用户决定 |
| `RESEARCHING → EVIDENCE_REVIEW` | 可回读搜索/读取回执、来源与冲突矩阵；证据不足进入 `NEEDS_SOURCE` |
| `DRAFTING → VISUAL_GENERATING → QA_PENDING` | 版本化正文、平台稿、实际图片文件与引用；任何一步失败只重做该步骤且留下原结果 |
| `QA_PENDING → NEEDS_FIX / READY_FOR_CONTENT_REVIEW` | 全部阻断项与证据、修订 hash；自动 QA 不授予内容批准 |
| `HANDOFF_PENDING → HANDOFF_CONFIRMED` | 精确冻结包、目标审核对象/回执、幂等键、读回状态；回包丢失停 `OUTCOME_UNKNOWN` 并先查询原回执 |
| `PAUSED / CANCELLED` | 从任一尚未不可逆提交的状态显式进入；停止新调用并保存现场。取消已提交的外部结果只停止后续步骤，不抹账、不冒称撤销成功 |
| `WAITING_RATE_LIMIT / WAITING_BUDGET / FAILED_RETRYABLE / FAILED_FINAL` | 记录恢复条件；仅确认“未执行”的安全读/生成步骤按相同幂等键重试。模型调用结果不明时先查 provider 回执/账单，不切供应商盲重做 |

`OUTCOME_UNKNOWN` 不是“失败”。对于生成、图片、移交、发布或互动尝试，先以原 `attempt_id`/provider 请求 ID/内容 hash 查询结果；若 provider 无可查询回执，则挂起并交人工核对，保留成本占用与发布配额，不用新请求补猜。`PUBLISHED_ID_PENDING` 保留现有平台语义：提交可能成功但公开 ID 待确认，不能补发或伪造链接。所有异步回包必须核对当前工作区、账号、任务、修订与页面代际，迟到回复不能覆盖新客户视图。

最小持久对象及写入界面：`LeadEvent` 保存渠道事件和规范 URL；`SourceEvidence` 保存来源、时间、权利、抓取哈希及主张引用；`ProductionRun`/`StepAttempt` 保存状态、租约、预算和 provider 回执；`ContentVersion` 保存父版本及各平台正文哈希；`MediaAsset` 保存实际文件、角色、顺序、尺寸与 SHA256；`QualityDecision` 保存规则/人工结论和依赖哈希；`HandoffReceipt` 保存现有审核链的精确对象与回读状态。每个对象含 `workspace_id`、创建/更新时间、操作者或服务身份、审计事件；账号绑定对象另含明确 `account_id`。写入命令使用服务器校验的 scope、命令 ID 和期望修订，读接口按 scope 分页，不以模型返回的 JSON 直接执行数据库或发布动作。

版本树以 `content_version_id`、父版本、修订原因、来源集 hash、正文 hash、各平台稿 hash、媒体清单 hash 和 QA/审批事件组成。内容可从同一线索派生不同日期或平台版本；旧批准仍指向旧精确版本，不传给后代。修改事实、正文、引用、图片字节/来源/角色/顺序、目标账号或平台后，依赖它们的事实/语言/视觉/图文 QA 及批准立即失效，进入相应重新核验；旧任务与已发布证据保留原貌。已发布 TCL/比亚迪/歌尔不得因规范升级自动重写。

## 6. 纪实写作与视觉契约

默认文风是有来源支撑的纪实报道：写清人物、时间、地点、其面对的约束、作出的决策、执行过程、可证实的结果与转折；时间线和数字须对应证据。建议、推论、预测要与已发生的事实分开标记。不能编造采访、对话、业绩、因果或成败；标题不能比证据更确定。编辑保存的风格规范有独立 `style_guide_version`、生效范围、审批人与变更记录，生产任务冻结所用版本；**不自动继承 ChatGPT 记忆、临时聊天口味或其他客户样稿**。不同平台稿分别审校语气、长度、标签与媒体契约，不以一个平台稿替补另一个。

视觉必须由实际获准的 imagegen 能力产生可核实文件；代码绘制、SVG 模板、占位图或仅有 prompt 不能报成“成品信息图”。生成前先把已核事实、统计口径、品牌权利和需要表现的信息结构编为图像 brief；生成后保存 provider、模型版本、prompt/输入版本、原始输出文件、mime、像素宽高、字节数、SHA256、时间、费用回执和权利状态。文字/数字的 OCR 及人工目检要逐项回扣正文事实卡；密图的视觉密度不等于把小字堆满手机屏。

封面是独立资产，摘要备份不是正文。`PUBLIC_FINAL` 必须有完整、唯一且有序的 BEGIN/END；正文只采区间内图片，第一张**正文**图为高密度信息图，可跟在有判断的短开篇之后。[`4aa4b44` 摄入修复与合成回归](v3-docx-public-final-20261023.md)已阻止备份图越界，但不证明极兔/宗申真实素材已正确。图像原像素比例、导出文件比例和 Publisher/平台最终显示须分别验收：9:16 原图不能未经判断强制拉成 2:3；缩放使用等比适应或显式生成另一版并重做 QA。分别检查原尺寸文字/数字、390px 手机可读性、原生导出和 Publisher 实际渲染；真实平台裁切需在明确平台/账号预览中核验。缺失、损坏、主题串题、数字错误、严重拉伸或无法读取原图均阻止 `READY_FOR_CONTENT_REVIEW`。

内容包至少含 `PUBLIC_FINAL` 正文、各渠道明确稿、首图/封面角色与顺序、媒体文件及哈希、来源权利/引用、事实卡、QA 证据和谱系。哈希绑定的是**实际输出文件**；更换来源图、重新生成、裁切或重压缩都会产生新媒体版本并使旧图文 QA/批准失效。图片不从相似文章、三位尾号或另一客户/账号自动借用。

## 7. 模型与 ChatGPT 接入路线

先以供应商中立接口设计 `ResearchAdapter`、`DraftAdapter`、`ImageAdapter` 和 `ReceiptReader`。MVP 只挑经授权且可测的供应商组合，不在本 PRD 写死某个收费模型。输入/输出用版本化 schema 和业务校验；结构化输出可减少解析歧义，**不证明事实真实**。[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)提供 schema 约束示例；[图像生成文档](https://developers.openai.com/api/docs/guides/image-generation)说明正式生成/编辑接口与模型资格，具体型号、价格和可用性实施时重新核验。

| 方向 | 可能用途与优先级 | 前置条件与不可推断的能力 |
| --- | --- | --- |
| **Publisher → 正规模型 API** | MVP 研究、结构化主张、写稿、实际 imagegen；服务端保存凭据与回执 | 单独的 API 组织/账单、明确预算/授权、模型与工具资格、数据使用约束。ChatGPT 订阅与 API 是不同计费系统，[官方计费说明](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)。不能把订阅额度当可共享 API 池 |
| **ChatGPT → Publisher 受控工具** | 后续让用户在 ChatGPT 经已批准 MCP/Actions 创建线索、读取任务、请求草稿等 | 受支持的连接、工作区/角色授权、按动作范围和确认；工具服务仍核验 Publisher 工作区与 account 权限。自定义 MCP 可提供工具，但资格、发布及写动作治理受计划/工作区限制，[官方连接说明](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt)。这不是 Publisher 任意读取/写入既有聊天 |
| **Workspace Agents / Sign in with ChatGPT** | 候选入口或身份/计划选项；有资格时另立集成验收 | 当前用户、工作区、区域、管理员开关、合作资格、OAuth 范围待核。Workspace Agents 有工作区控制，[官方说明](https://help.openai.com/en/articles/20001143-chatgpt-workspace-agents-for-enterprise-and-business)；商业网站 Sign in with ChatGPT 当前为有限资格，[官方 quickstart](https://developers.openai.com/siwc/quickstart)。登录权限不等于聊天记录或 API 资源权限，也不自动免 API 账单 |
| **受控浏览器操作 ChatGPT** | 极端兜底的人工在环研究/草稿实验，不是 MVP 稳定生产链 | 仅现有授权会话、许可用途、可观察步骤与成本回执；不绕登录、验证码、风控或限制，不读取秘密。回包未知先对账，不能静默换浏览器/API 重复支付或生成；不把网页 UI 当官方后台 API |

每个适配器上报实际供应商、模型/工具版本、请求 ID、输入/输出 hash、token/图片计量（若 provider 提供）、报价依据、实际账单状态、耗时、超时/限流类别、是否可对账。每客户/任务设硬预算与单步预算、最大研究轮数及人工放行阈值；预计成本超限前暂停，账单结果未知时预留预算并对账。不能假设跨模型额度共享、每天重置，或切换供应商后原请求免费；不写虚构日程/单篇成本。确定未执行的调用可有界退避重试；可能执行过的调用只能同请求回查或人工裁定。降级模型须显示质量差异和重新 QA，不能暗中替换已批准版本。

## 8. 权限、批准与现有发布链

线索的 `workspace_id` 是读写第一道边界。客户 A 的来源、预算、提示词、模型回执、图片、QA、任务与审计不可由客户 B 查看、搜索或复用；同客户共享来源不携带源账号审批。选定平台与目标账号后，平台稿/许可/节奏/警告与执行证据固定到该账号，切换账号重走目标检查。服务端以可信登录身份和持久存储校验，不能用网页传入的 account 名称、模型文本或 ChatGPT 会话作为授权证据。

生产任务完成只表示材料达到**待内容审核**；内容批准表示某精确正文与媒体版本已获内容层决定；特定账号发布权限表示该账号、平台、目标与额度均允许相应动作。三者不可互相推出。撤销、来源过期、权利变化或改稿使相应批准失效；历史回执仍可审计。沿用已有正常运营节奏和许可条件，不额外为所有发布强加“一篇一确认”，但也不新增任何外发授权。本提案的 MVP 不调用真实发布、评论、私信或群组动作。

## 9. 验收案例与阶段退出条件

每例要保存输入、所选客户/账号、步骤回执、最终状态与版本/媒体哈希；合成环境通过不等于正式 Site 或平台通过。

| 案例 | 必须观察到的结果 |
| --- | --- |
| URL 含 prompt 注入、内网跳转或超长响应 | 当不可信内容展示并标注；不执行其中命令，不访问内网或泄露凭据，阻断或限制抓取 |
| 同一聊天事件重复投递、同 URL 不同事件、转载/新事实 | 相同 `event_id` 回同一线索；近重复给出处与理由；明确新版本可产生子版本，旧稿不被吞 |
| 来源矛盾、过时、权利不清 | 主张留待核与来源时间；无权图片不进入生成/发布包 |
| 虚构数字、图中文字与正文冲突、图片串题 | 事实/视觉/图文 QA 阻断并定位到精确主张、文件和版本；模型自报通过无效 |
| 首图为封面/备份、缺图、9:16 被拉为 2:3 | `PUBLIC_FINAL` 范围/顺序正确，缺图不 READY；原像素、390px、原生导出与 Publisher 实际渲染各留证，不强制扭曲 |
| 更换图片来源或编辑正文后旧批准 | 相关 QA 与批准失效；旧冻结快照保留，重新检查后才产生新内容决定 |
| 断线、重复点击、回包丢失、重启 | 同一事件/步骤/移交仅一项持久结果；`OUTCOME_UNKNOWN` 先对账，不重复生成、扣费或发布 |
| 模型限流、预算耗尽、切供应商 | 显示等待原因、已消耗与待对账额；暂停而不假定额度重置，恢复后沿原任务谱系 |
| 超过 200 个版本查找 | 可以继续加载且明确搜索范围；完整 ID/slug/版本定位正确，不能把“本页无结果”说成全库无结果 |
| 跨账号/跨客户迟到响应与成员撤销 | 旧回复不能污染新视图、恢复旧选稿或携带旧批准；服务端重新校验精确范围 |
| 平台 UNKNOWN / `PUBLISHED_ID_PENDING` | 保留原尝试及占用，只回读或人工对账；不再发、不编公开 ID |

**阶段 0：正式运行底座**。退出条件是原私有 Site 的官方支持构建、可信身份、D1/R2 与重媒体绑定在真实托管环境通过隔离/重启/移动端验收；不以本地 SQLite/合成登录代替。

**阶段 1：URL/手工生产 MVP**。退出条件是上述输入到精确待审核移交的全链持久回执、实际 imagegen 文件、来源/权利/QA/预算阻断、修改后失效、断线恢复和真实用户可用性验收；发布仍按已有独立授权。

**阶段 2：聊天转发与 @**。仅在受支持渠道的权限与 `event_id` 语义验明后接入；同一消息重放幂等，用户能从聊天或工作台查到同一任务，写动作不越权。

**阶段 3：主动发现与运营反馈**。先限定来源/频率/范围与读权限，形成候选选题和指标观察；互动、发布及下一版生产分别经过既有账号许可和内容门槛。真实平台读回、定义/时间窗、空值与失败历史可核后才可称“闭环”。不承诺任何固定日程、成本或自动成功率。

上线后观察线索重复误判、关键主张有据率、各 QA 阻断与人工修订原因、从线索到合格待审包的耗时、每个被接受版本的实际模型费用、未知结果队列年龄、图片在 390px 的可读性退回率，以及来源撤回后失效传播是否完整。指标须带客户、版本、时间窗和分母定义；先取得基线再定目标，不能用生成次数或点击量冒充发布效果。

待决策：首批客户与内容权利边界、第一组经授权的研究/文图模型、每客户预算、风格规范负责人、正式来源注册与审核责任人、哪些渠道允许接入、现有发布节奏与人工介入点。做选择前不创建凭据或调用收费服务。
